# Reval 2.9.0 — «موتور هوشِ برنامه‌ریزی: زمان از محتوای فصل درمی‌آید»

**تاریخ:** ۱۳ آبان ۱۴۰۵ · **نوع:** بازنویسیِ هستهٔ زمان‌بندی · **نسخهٔ قبل:** ۲.۸.۱۵

---

## ۱) شکایتِ اصلی و ریشهٔ فنیِ آن

> «برنامه‌ریزی درست نیست و با واقعیت هم‌خوانی ندارد — یک فصلِ کاملِ ریاضی در یک جلسهٔ ۳۰ دقیقه‌ای.»

ریشه در یک خط فرمول بود:

```js
// ۲.۸ و پیش‌تر
need = base(۶۰/۸۵/۱۲۰) × سختی‌درس × ضریبِ اهمیتِ فصل
```

سه ایرادِ ساختاری داشت:

1. **زمان هیچ ربطی به حجمِ فصل نداشت.** «مشتق» و «آمار» هر دو از یک `base` می‌آمدند.
2. **اهمیت و سختی در یک عدد ضرب می‌شدند.** فصلِ پرتکرار «سخت‌تر» حساب می‌شد، در
   حالی که اهمیت باید فقط *عمقِ تمرین و تعدادِ مرور* را زیاد کند، نه زمانِ فهمیدن را.
3. **هیچ سبدی برای «تثبیت»، «تمرین» و «سنجش» نبود.** یک عددِ «نیاز» می‌ماند که
   موتور آن را با بلوک‌های ۳۰ دقیقه‌ای می‌خورد و بعد فصل را «خوانده‌شده» علامت می‌زد.

اندازه‌گیریِ واقعی روی نسخهٔ ۲.۸.۱۵ (رشتهٔ ریاضی، ۲ ساعت در روز):

| سنجه | ۲.۸.۱۵ | ۲.۹.۰ |
|---|---|---|
| سهمِ جلسه‌های یادگیریِ ریاضی ≤ ۳۰ دقیقه | **۴۸٪** | **۰٪** |
| میانهٔ طولِ جلسهٔ ریاضی | ۳۵ دقیقه | ۴۲ دقیقه |
| جلسه‌های بلوکِ «تثبیت» | ۰ | موجود (۲۰–۳۵ دقیقه) |
| سندِ بودجهٔ فازها برای هر فصل | نداشت | دارد (یادگیری/تثبیت/تمرین/سنجش/مرور) |

## ۲) مدلِ تازه: از «حجمِ محتوا» تا «طرحِ جلسه»

### ۲.۱ سه بُعدِ کاملاً جدا

| بُعد | منبع | اثر |
|---|---|---|
| **سختیِ درس** | `minutesPerPage` و `minutesPerNewConcept` (ریاضی ۲۰ دقیقه/مفهوم، زیست ۹) | فقط سرعتِ یادگیری |
| **حجمِ فصل** | `chapter-size.js`: صفحه، مفهومِ نو، تمرینِ همان فصل | فقط مقدارِ کار |
| **اهمیتِ فصل** | کاتالوگِ کنکور (تیر ۱ تا ۵) | فقط عمقِ تمرین (×۱٫۲) و مرورِ اضافه |

### ۲.۲ فرمول‌ها (از گزارشِ پژوهشی، بخش ۳)

```
Learn       = s · [ w_p·(P·a) + w_c·(N·m) ]
Practice    = max( Learn·p/l , N_ex·e·s ) × (۱٫۲ اگر تیر ≥ ۴)
Consolidate = Learn · c/l
Assess      = Learn · q/l
Review_k    = max( ۸ , T0 · r_k )
```

`s` = ضریبِ فردی: `clamp(1 − 0.006·(m_eff − 50), 0.8, 1.4)` با `m_eff = 0.5·تسلطِ اعلامی + 25`.

### ۲.۳ اعتبارسنجی با نمونهٔ کارشدهٔ گزارش — فصلِ «مشتق»

| کمیت | گزارش | خروجیِ موتور ۲.۹.۰ |
|---|---|---|
| صفحه / مفهوم / تمرین | ۳۰ / ۶ / ۴۵ | ۳۰ / ۶ / ۴۵ |
| Learn | ۱۹۴ | ۱۹۴ |
| Practice | ۳۴۹ | ۳۴۹ (۳۷۹ با ضریبِ تیرِ ۵) |
| Consolidate | ۶۵ | ۷۰ |
| Assess | ۹۷ (سقف ۴۵) | ۴۵ |
| T0 | ≈۷۰۵ | ۸۶۲ (با تیرِ ۵) |
| تعداد جلسه | ۱۴ | ۱۴ |
| مجموعِ مرورها | ۱۵۸ دقیقه | ۱۵۸ دقیقه |

### ۲.۴ طرحِ جلسه (Session Composer) — هیچ جلسهٔ بی‌معنا

| نوع جلسه | بازهٔ مجاز | کفِ معنادار |
|---|---|---|
| مفهوم + نمونهٔ حل‌شده | ۳۵–۵۰ | **۳۵** |
| تمرینِ هدایت‌شده | ۴۵–۶۰ | ۴۰ |
| تمرینِ مستقل + تست | ۴۵–۶۰ | ۴۰ |
| تثبیت و جمع‌بندی | ۲۰–۳۵ | ۲۰ |
| بازیابی | ۱۰–۲۰ | ۱۰ |
| سنجشِ فصل | ۱۲–۲۵ | ۱۲ |
| مرورِ فاصله‌دار | ۸–۳۰ | ۸ |

هر جلسهٔ یادگیری با **۵ دقیقه بازیابی** بسته می‌شود و از جلسهٔ دوم با **۱۵ دقیقه
بازیابی** باز می‌شود. هیچ روزی که یادگیری دارد، بدونِ بازیابی نمی‌ماند.

### ۲.۵ نردبانِ مرور بر اساسِ افقِ آزمون

| افق | فاصله‌ها (روز) | تعداد |
|---|---|---|
| ۳۰ | ۱، ۴، ۱۰، ۲۰ | ۴ |
| ۹۰ | ۲، ۷، ۱۷، ۳۸، ۶۵ | ۵ |
| ۱۸۰ | ۳، ۱۰، ۲۴، ۵۲، ۱۰۰، ۱۴۵ | ۶ |
| ۳۰۰ | ۴، ۱۴، ۳۴، ۷۵، ۱۴۰، ۲۲۰ | ۶ |

بین ستون‌ها **درون‌یابیِ لگاریتمی** می‌شود؛ آخرین پله هرگز از `۰٫۷۵×افق` بیشتر
نمی‌شود و طولِ هر مرور کسری از زمانِ اولیهٔ همان فصل (۲–۶٪، کفِ ۸ دقیقه) است.

### ۲.۶ باندهای تسلط

| تسلط | تصمیم |
|---|---|
| ≥ ۸۰٪ | «مهار» — فقط مرورِ فاصله‌دار |
| ۶۵–۸۰٪ | «ارتقا» — تمرینِ هدفمند + تحلیلِ خطا |
| < ۶۵٪ | «بازآموزی» — یادگیریِ دوبارهٔ هدفمند (حداکثر ۲ دور، آزمونِ مجدد ۲–۳ روز بعد) |

### ۲.۷ سیاستِ کمبودِ وقت

```
اولویت = سهمِ وزنی × (۱ − تسلط) ÷ زمانِ لازمِ فصل
```

وقتی فصلِ نخوانده زیاد است، سهمِ تستِ روز تا ۲۵٪ پایین می‌آید (نه پوششِ فصل‌ها)،
فصل‌های کم‌تیر عمقِ کمتری می‌گیرند و **فصلِ تیر ≥ ۳ هرگز کنار گذاشته نمی‌شود**.
هر کمبودی که جبران‌شدنی نباشد، صریح اعلام می‌شود: «پوشش ۵۵٪ — برای پوششِ کامل
روزی ۳٫۱ ساعت لازم است».

### ۲.۸ تمرینِ درهم

سهمِ تست‌های هر جلسه که از **فصل‌های قبلیِ همان درس** می‌آید:
ریاضی ۴۰٪ · فیزیک ۳۵٪ · شیمی ۲۵٪ · زیست ۱۰٪ · زمین ۵٪ · دروسِ حفظی ۰٪.
از جلسهٔ سومِ تمرینِ هر فصل فعال می‌شود و در برچسبِ بلوک نوشته می‌شود
(«— تست هدفمند · درهم: ۴۰٪ فصل‌های قبل»).

### ۲.۹ بارِ روزانه

| قاعده | مقدار |
|---|---|
| سقفِ مؤثرِ روز | ۱۰٫۵ ساعت (هرگز ۱۲) |
| خواب | دست‌کم ۷٫۵ ساعت |
| حاشیهٔ امنِ برنامه‌ریزی | ۸٪ (قبلاً ۱۵٪ — ساعتِ اعلامی هدر می‌رفت) |
| درس در روز | ≤ ۴ ساعت → ۲ درس · ۵–۸ → ۳ درس · > ۸ → ۴ درس |
| سهمِ یک کتاب | ≤ ۶۰٪ روز |

## ۴) ستونِ تازه در «ارزیابی فصل به فصل»

هر فصل حالا یک نوارِ بودجه دارد:

```
یادگیری (آبی) · تثبیت (بنفش) · تمرین/تست (نارنجی) · سنجش (قرمز) · مرور (سبز)
۳٫۴ ساعت · ۹ جلسه
```

و با نگه‌داشتنِ نشانگر روی نوار: تفکیکِ دقیقه‌ای + حجمِ فصل (صفحه، مفهومِ نو، تمرین).

`model-params.js` و `chapter-size.js` عوض می‌شوند.

## ۶) صداقتِ داده — چه چیزی برآورد است

- **تعدادِ صفحه/مفهوم/تمرینِ فصل‌ها برآوردِ ساختاری است** (کتاب‌های درسی در دسترسِ
  ما نبودند). مبنای آن حجمِ نسبیِ فصل‌ها در کتاب و چگالیِ هر درس است؛ با
  «شروع/پایانِ مطالعه»ی واقعیِ کاربران قابلِ کالیبراسیون است.
- **دقیقه‌به‌ازای‌صفحه و دقیقه‌به‌ازای‌مفهوم** از گزارش (ستونِ اطمینان: برآوردِ
  کارشناسی، نه آزمایشِ کنترل‌شده).
- **اعدادِ تکرارِ فصل‌ها در کنکور** از منبعِ غیررسمی می‌آید (گزارش، بخش ۴-۴) و
  همان‌طور که در ۲.۸.۱۲ گفتیم، فقط برای *اولویت* استفاده می‌شود، نه برای حذف.
