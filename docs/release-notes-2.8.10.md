# روال ۲.۸.۱۰ — «روز سبک» حالا خودش را توضیح می‌دهد

> ادامهٔ بازرسی نسخهٔ ۲.۸.۹: یکی از مواردی که در شبیه‌سازی دیدم، روز «سبک» بود.

## مشکل
در «روزهای خارج از برنامه» (قدم ۳) می‌شود یک روز را **«روز سبک»** گذاشت: برنامه بار آن روز را
عمداً به ۵۵٪ می‌رساند و کارِ جامانده را به روزهای بعد می‌برد. ولی **یادداشت آن روز خالی می‌ماند** —
کاربر فقط می‌دید امروز نصفِ روزهای دیگر است، بدون اینکه بداند چرا. (روز «تعطیل کامل» از قبل دلیلش را می‌نوشت.)

## حالا
روی همان روز نوشته می‌شود:

> **روز سبک (مهمانی): بار امروز عمداً ۵۵٪ روز عادی است و کارِ جامانده به روزهای بعد می‌رود.**

- اگر برای روز یادداشتی نوشته باشی (سفر، بیماری، مهمانی…)، داخل پرانتز همان می‌آید.
- درصد از تنظیمات واقعی خوانده می‌شود، نه عددِ دستی در متن.
- روز «تعطیل کامل» مثل قبل دلیلش را نشان می‌دهد.

## برای توسعه‌دهنده‌ها
دستورهای آماده اضافه شد:

```bash
npm test          # همهٔ آزمون‌های موتور و شبیه‌سازی (۱۰ مجموعه)
npm run test:engine   # فقط شبیه‌سازی ۷ دانش‌آموز
npm run test:ui       # آزمون سرتاسری رابط کاربری در Electron
npm run build:win     # ساخت نصب‌کننده ویندوز
npm run build:patch   # ساخت وصلهٔ کد
```

## آزمون
`sim-students` از **۱۴۰** به **۱۴۵** بررسی رسید؛ چهار بررسی تازه فقط برای همین موضوع:

- بار روز سبک کمتر از روز عادی است؛
- یادداشت روز سبک خالی نیست و نام رویداد را دارد؛
- درصد بار روز در همان یادداشت نوشته شده؛
- روز تعطیل کامل خالی است و دلیلش نوشته شده.

بقیهٔ مجموعه‌ها سبز: `ui-full-flow` ۵۷ · `simulation-year` ۹۲/۰ · `v28-ai` ۹۱ · `v27` ۵۴ · `v26` ۱۰۸ · `v25` ۱۰۳ · `v24` ۴۲ · `capacity` ۵۵ · `deadline` ۴۲ · `deadline-general` ۱۷ · `patch` ۴۶ · `ui-ai-fab-left` ۱۱ · `ui-book-deadline-general` ۸ · `ui-exam-subject-checks` ۱۱ · `ui-chapter-importance` ۱۵ · `ui-assess-first` ۱۰ · `ui-chapter-titles-all` ۱۷ · `ui-chapter-names` ۱۵ · `ui-ai-preview` ۱۸ · `ui-ai-close` ۱۶.
