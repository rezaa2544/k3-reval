# روال ۲.۸.۱ — رفع اشکال: پنجرهٔ گفت‌وگو حالا کامل بسته می‌شود

> «می‌خوام صفحه چت رو ببندم ولی بسته نمیشه و کنار نمیره.»

این یک اشکال واقعی در CSS بود و رفع شد.

## چه اتفاقی می‌افتاد؟

پنل گفت‌وگو یک `<aside>` است و در استایل برنامه یک قاعدهٔ سراسری وجود دارد:

```css
main, aside, .modal-card, .mbox, .view { direction: ltr }
```

این قاعده جهتِ چیدمانِ پنل را `ltr` می‌کرد، در حالی که برای بسته‌شدن پنل دو قاعدهٔ هم‌زمان داشتیم:

```css
#aiPanel      { inset-inline-start: 0; transform: translateX(-104%) }   /* بسته */
[dir="rtl"] #aiPanel { transform: translateX(104%) }                    /* بسته */
```

نتیجه: پنل بسته، به‌جای بیرون رفتن از لبهٔ چپ، **۱۰۴٪ به راست** (یعنی وسط صفحه) هُل داده می‌شد. برای همین:

- همان کادری که می‌بستی، وسط صفحه می‌ماند؛
- و چون واقعاً روی صفحه بود، **جلوی کلیک‌های تو روی برنامه را هم می‌گرفت**.

## چه چیزی عوض شد؟

| | |
|---|---|
| **چیدمان فیزیکی** | پنل با `left: 0` و `transform: translateX(-104%)` کار می‌کند — مستقل از `dir` سند و از هر قاعدهٔ سراسری. دیگر هیچ‌وقت وسط صفحه نمی‌ماند. |
| **`direction: rtl` روی خودِ پنل** | متن و حباب‌های گفت‌وگو راست‌به‌چپ می‌مانند. |
| **`visibility: hidden` در حالت بسته** | پنلِ بسته حتی اگر جایی رندر شود، هیچ کلیکی را نمی‌گیرد. |
| **دکمهٔ شناور دوحالته** | وقتی چت باز است، خودِ دکمهٔ پایین صفحه به **«بستن ✕»** تبدیل می‌شود. |
| **Esc** | هر جا که باشی، Esc گفت‌وگو را می‌بندد. |
| **کلیک بیرون** | کلیک روی هر جای دیگرِ برنامه پنل را می‌بندد. |
| **لایهٔ تاریک روشن‌تر** | از ۲۸٪ به ۱۸٪ رسید تا برنامه پشتِ چت خوانا بماند. |

## چهار راه برای بستن (همه آزمایش‌شده با کلیک واقعی ماوس)

1. دکمهٔ **✕** بالای پنجره
2. کلید **Esc**
3. **کلیک بیرون** پنجره
4. دکمهٔ شناور پایین صفحه (که در حالت باز، خودش **«بستن»** است)
